# Scorer audit, 2026-11-14 — incomplete

The requested audit of several hundred plays has **not** been performed, and no count of
misclassified hits is available. `bb_game::game::classify_bip` is a provisional diagnostic:
it denies a hit on any other runner put out after an infielder secures the ball. Under
[2026 OBR 9.05(b)(3)](https://www.baseball.ca/uploads/files/2026%20Rules/2026%20MLB%20Official%20Rules%20-%20EN.pdf),
the preceding runner must be trying to advance one base or return. Force outs are treated
separately under 9.05(b)(1). A failed attempt is a hit if ordinary effort would not have
retired the batter at first, 9.05(a)(6); otherwise it is a choice, 9.05(b)(4).

The saved pitch records do not yet contain the timed first-base touch, first fielder to
handle the ball, choice of throw, or noise-free reference-throw timing needed to audit
these rulings. An observed first secure possession is not necessarily first handling.
The event log's current `ScorerEvidence` table has a margin field but the writer does not
populate it. The simulator also does not identify errors. An audit count requires those
facts (and the starting base and destination of the runner) or independent play review;
it cannot be inferred honestly from the current hit/choice totals.

A new isolated decision helper covers the above OBR distinctions given evidence, but is
not connected to the log or box score. Its `Undetermined` result preserves the distinction
between missing evidence and an actual scoring decision. Captions now name the base of a
preceding runner's out when the provisional classifier calls a fielder's choice. No
physical outcome, event encoding, or game-log digest is intentionally changed.
