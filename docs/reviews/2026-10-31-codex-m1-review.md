Findings concern implemented behavior and tests. P1 = high priority, P2 = medium, P3 = low.

1. **[P1] A log missing its footer can be accepted as a finished log, silently dropping a play.** `sim/crates/bb_schema/src/log.rs:148` and `:163`. Every frame has the same identifier, so parsing the final frame as `LogFooter` does not establish its type. The game-digest check is skipped when the resulting `plays` vector is empty. **Failing scenario:** supply a valid header followed by `PlayRecord { play_index: 0, events: [] }`, with no footer. The probe returned `Ok(LogView)` with zero plays: the sole play was interpreted as the footer. A genuine zero-play footer with a missing or incorrect game digest is also accepted. This contradicts the finished-container and digest requirements in data-formats §§4.1, 4.4. **Suggested fix:** always require and verify a 32-byte game digest, including the zero-play case (expected digest: 32 zero bytes), and require the footer's per-play list. Add missing-footer and zero-play digest regression tests; use an explicit frame discriminator if positional parsing cannot otherwise distinguish supported frame shapes.

2. **[P1] Short size-prefixed frames panic instead of returning a parse error.** `sim/crates/bb_schema/src/log.rs:124`. The parser checks that the declared payload fits, but not that the frame contains the size prefix, root offset, and four-byte identifier. FlatBuffers' `buffer_has_identifier(..., true)` asserts that its input has at least 12 bytes. **Failing scenario:** `frames(&[0, 0, 0, 0])` panics; `read` inherits the panic. Payload lengths 1–7 also reach this assertion when those bytes are present. **Suggested fix:** reject frames shorter than 12 bytes before the identifier call, and use checked arithmetic for `i + 4 + n` so malformed lengths also return errors on 32-bit targets. Add tests covering every short length and oversized prefixes.

3. **[P2] End-cap contacts produce a zero or incorrectly directed normal.** `sim/crates/bb_physics/src/contact.rs:128`–`:130`. The gap calculation clamps the axial station at the bat's ends and includes axial distance in the cap-sphere gap, but the normal calculation always removes that axial component. **Failing scenario:** a stationary bat has its axis along +X and knob at the origin; a ball approaches its tip along −X. At the contact selected by `gap`, `r - p` is parallel to X, so `reject(bat.axis)` is zero. The barrel slope at the tip is also zero, yielding `n = 0`. `resolve_contact` then classifies the contact as separating, returns zero impulses, and leaves the incoming ball velocity unchanged. Oblique cap contacts similarly lose their axial normal component. This contradicts the cap-sphere treatment in physics-spec §7. **Suggested fix:** compute cap normals from the cap sphere's actual center-to-ball vector, with separate handling for the side/taper surface. Test axial and oblique contacts at both ends, asserting a unit normal and a nonzero impulse for approaching balls.

4. **[P2] Plane-tilt execution error can have no effect on the swing.** `sim/crates/bb_agents/src/swing.rs:209`–`:211`. `apply_placement` rotates the attack direction around `axis_c × Z`, then projects it perpendicular to the bat axis. That is not the axis that changes the attack angle while holding the bat axis fixed. **Failing scenario:** plan a reachable swing with `axis_c = +X` and attack angle zero, giving `e_v = +Y`. A placement with only `plane_tilt = 0.1` rotates +Y around −Y, so the direction is unchanged and the executed swing is identical to the intended swing. With a nonzero initial attack angle, this geometry instead gives `atan(tan(attack) * cos(plane_tilt))`, an even response to positive and negative errors. BatControl's plane-tilt noise therefore loses its intended sign and first-order effect (agent-models §§3.6, 10). **Suggested fix:** rebuild the desired attack direction at the perturbed angle and project it into the allowed plane, or rotate about the bat axis with the appropriate handedness. Test positive and negative tilt deviations for both batting sides and a horizontal initial attack.

5. **[P2] The collision energy guard does not guarantee its stated postcondition.** `sim/crates/bb_physics/src/collision.rs:99`–`:104`. A retry with `e_t = 0` is returned without checking its energy; an original `e_t = 0` result bypasses correction altogether. Normal/tangential coupling in `K` means zero tangential restitution alone does not ensure dissipation. **Failing scenario:** a synthetic rigid body with `inv_mass = 1`, `inv_inertia = diag(1, 1, 1000)`, `r = (1, -0.1, 0)`, `v = (-1, -100/11, 0)`, `w = 0`, against `Body::immovable(0)`, with `n = +X` and material `(e_n, e_t, mu) = (0.55, 0.15, 0.5)`. All inertia eigenvalues are positive. The probe returned `energy_guard = true`, but total energy increased from **41.8223140496 J to 41.9266134606 J**. Starting with `e_t = 0` gives the same gain with `energy_guard = false`. This violates physics-spec §8.1 step 5 and A11. **Suggested fix:** check every returned candidate, including the retry, and use a verified dissipative fallback or an explicit solver error if it still gains energy. Extend A11 with a coupled-contact case that actually exercises the guard and verifies the retry's energy.

6. **[P2] The default COR profile puts the specified taper-start value at the wrong station.** `sim/crates/bb_physics/src/bat.rs:188` and `:212`–`:215`. Physics-spec §6.1 defines the taper from 11 to 22 inches; §8.2 places `f_taper = 0.55` at its start. The implementation instead sets `u_taper` to 22 inches and explicitly reinterprets the spec as the barrel end of the taper. **Failing scenario:** on the default 34-inch bat, `location_factor(11 * INCH, length)` returns **0.35**, rather than the specified **0.55**. At 22 inches it returns 0.55, whereas the specified quadratic from the 11-inch taper start to the sweet spot gives approximately 0.943. This substantially lowers normal COR over the outer taper and is a model deviation rather than rounding. **Suggested fix:** use the specified 11-inch taper start in the default parameter, or obtain an explicit spec change for the intended alternative profile. Add tests for the handle, taper start, sweet spot, and tip against the specified factors; A8 currently solves for its own COR and does not validate `BatBallParams`.

7. **[P2] Bat contact uses stale spin and does not rebuild the ball state at the event time.** `sim/crates/bb_physics/src/contact.rs:123`–`:131`. The detector takes position/velocity from Hermite interpolation and spin from the preceding whole-step knot. Spin is not piecewise constant: it decays continuously in the full-state RK4 model. Physics-spec §§5.1, 5.3 require re-integrating a partial step to reconstruct the event state. **Failing scenario:** contact occurs 1 ms into a pitch step whose starting spin magnitude is 250 rad/s, airspeed is approximately 40 m/s, and `tau100 = 22 s`. The stored contact spin remains 250 rad/s, while partial-step integration gives approximately 249.9898 rad/s. This stale input feeds the friction impulse and outgoing spin, and moving the same contact across an integrator boundary introduces a spin discontinuity. **Suggested fix:** pass the flight environment into event-state reconstruction and partially integrate from the preceding knot to the detected contact time. Keep Hermite interpolation for locating the event. Test an interior-of-step contact with finite spin decay against `env.step` for the corresponding partial duration.

8. **[P2] Invalid integration steps cause an unbounded loop and allocation.** `sim/crates/bb_physics/src/flight.rs:225`–`:248`. `fly` accepts arbitrary `dt` without checking that time advances. **Failing scenario:** with `t0 = 0`, `dt = 0`, `t_max = 1`, and no stops, every iteration appends a knot at time zero, and the loop never terminates. A negative step moves time away from the deadline. Even a positive step can fail to advance when it is smaller than the floating-point spacing at `t0`. These cases follow directly from the loop; the unbounded allocation was not run. **Suggested fix:** require finite times, a finite positive step, and a finite nonnegative duration, then reject any iteration for which `cur.t + h <= cur.t`. Add rejection tests rather than timeout-based tests.

9. **[P2] Endpoint-only bracketing misses a return to a surface within the first step.** `sim/crates/bb_physics/src/flight.rs:231`, with the same limitation in `Trajectory::find` at `:196`. Requiring the step's starting gap to be strictly positive misses a flight that starts on the boundary, rises above it, and crosses downward before the next knot. **Failing scenario:** vacuum flight from `r.z = R`, `v.z = 0.01 m/s`, zero other velocity/spin, `dt = 0.005 s`, stop `ZBelow(R)`, duration `0.01 s`. The downward crossing is at **2·0.01/9.80665 ≈ 0.00203943 s**. The probe instead returned `stop = None`, ending **0.3903325 mm below** the surface. The Hermite segment contains the missed positive excursion. This fails physics-spec §5.3's event detection requirement. **Suggested fix:** bracket directional roots using the interpolant's extrema as well as its endpoints, distinguishing departure at the initial boundary from a later return. Test this short flight and the corresponding `find` query.

10. **[P2] Failed aiming solves are silently promoted to executable pitch plans.** `sim/crates/bb_agents/src/pitcher.rs:138`–`:139`; failure originates in `sim/crates/bb_physics/src/pitch.rs:116`–`:129`. `aim_at_plane` can stop without a crossing or exhaust its iterations with a large residual, but `plan_release` discards the residual, iteration count, and flight time and returns an ordinary `IntendedRelease`. **Failing scenario:** with the default environment and standard release point, use shape `(speed, spin_rate, axis, efficiency, gyro_sign) = (41.8, 230, 210, 0.92, 1)` and target `(0, 100)` m. The probe returned `residual = infinity`, `iterations = 0`, and `flight_time = 0`; the caller's conversion to a plan has no failure check. A zero-speed shape similarly cannot produce a valid aim. This breaks the noise-free intent contract in agent-models §2.3. **Suggested fix:** return an explicit aiming failure for missing crossings, nonfinite inputs/results, or a residual above tolerance, and propagate it from `plan_release`. Test unreachable targets and iteration exhaustion alongside the existing successful solves.

11. **[P2] Per-play digest metadata is not fully verified.** `sim/crates/bb_schema/src/log.rs:151`–`:160`; writer entry point at `:62`–`:65`. The reader permits an absent digest list, ignores stored `PlayDigest.play_index`, and never checks for extra list entries. The writer also lets the supplied index disagree with the index inside an already-built frame. **Failing scenario:** for a one-play log whose play has index 0 and whose digest is `d`, the probe accepted each footer variant: no per-play list; `[(99, d)]`; and `[(0, d), (1, arbitrary_digest)]`, provided the game digest was correct. `push_play_frame(99, frame_for_play_0)` can produce the index disagreement through the public writer. The per-play list therefore cannot reliably locate the divergent play as required by data-formats §4.4. **Suggested fix:** require exactly one digest entry per play, verify its index and 32-byte digest, and derive or validate the index when accepting a prebuilt play frame. Add independent tests for absent, extra, misindexed, and incorrectly sized entries.

12. **[P2] The supposedly open-interval uniform generator can return exactly 1.0.** `sim/crates/bb_math/src/rng.rs:111`–`:113`. Adding `0.5` after converting a 53-bit integer to `f64` rounds at the upper endpoint. **Failing scenario:** when `next_u64() >> 11 == 2^53 - 1`, the implemented expression evaluates to **1.0**, which the probe confirmed. This violates the documented `(0, 1)` contract and allows endpoint samples into Box–Muller and any future inverse-CDF consumer. The 10,000-sample test cannot meaningfully detect this rare word pattern. **Suggested fix:** use a conversion whose entire range is representable inside `(0, 1)`, such as a 52-bit midpoint construction, or reject the offending endpoint. Factor the word conversion so tests can directly exercise minimum and maximum words; account for the resulting change to deterministic draw outputs.

13. **[P2] The implemented release-noise contract has no regression tests.** `sim/crates/bb_agents/src/motor.rs:34`–`:61`. Existing agent tests cover noise-free aiming, arsenal bands, and tunneling; none calls `execute_release`. The normal-moment test in `bb_math` does not exercise release noise or its ±4σ truncation. **Concrete uncovered failure scenario:** swapping the speed and spin-axis draws, removing truncation, or changing the 2 cm release-point noise to 2 m would leave all 45 tests from the initial run passing (the added M2 sweep tests also do not exercise release noise), despite violating agent-models §§1.3, 2.3 and the function's fixed-draw-order replay contract. **Suggested fix:** add a fixed-key release fixture, a zero-noise identity case, component-wise ±4σ bounds, and a multi-key distribution check for the specified angular, speed, spin-rate, tilt, and release-point scales. Verify `command_mult` and the command factor through the public noise constructor.

14. **[P3] The spin-construction fallback loses all transverse spin for vertical velocity.** `sim/crates/bb_physics/src/spin.rs:68`–`:75`. For `v` parallel to Z, `Z.reject(vhat)` is zero, so both fallback basis vectors are zero. **Failing scenario:** `spin_from_axis(180, 1, 250, 1, Vec3::Z)` returns `(0, 0, 0)` instead of preserving the requested 250 rad/s rate. For efficiency 0.5 it retains only the gyro component, also producing the wrong total rate and efficiency. The requested projected axis can be geometrically unavailable for such a velocity, but silently deleting spin is not a valid resolution. **Suggested fix:** either reject velocities/axes for which this inverse is undefined, or document a fallback convention and construct its transverse basis from the coordinate axis least aligned with velocity. Add vertical-velocity tests that check the selected error or fallback behavior and preservation of spin magnitude.
